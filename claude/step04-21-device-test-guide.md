# step04-21 — 실기기 테스트 가이드 (preview APK)

작성일: 2026-09-12
전제: 웹 통합테스트 완료(`step04-20`). **웹에서 확인 가능한 항목은 전부 통과했다.**
이 문서는 **웹에서 확인이 불가능한 것만** 다룬다.

---

## 0. 왜 이것들만 실기기인가

| 항목 | 웹에서 불가능한 이유 |
|---|---|
| 푸시 | Expo 푸시 토큰은 **실기기에서만** 발급된다. 웹·에뮬레이터는 발급 자체가 안 된다 |
| 푸시 언어 | 기기 언어가 `push_tokens.lang`에 저장되어야 하는데, 그 등록이 실기기에서만 일어난다 |
| 지도 | `react-native-maps`는 웹을 지원하지 않아 웹에서는 placeholder가 뜬다 |
| 사진 업로드 | 카메라·갤러리 권한이 필요하다 |
| Google 로그인 | 웹 미리보기는 OAuth 콜백을 처리할 수 없다 |
| 업체 2곳 경쟁 | 계정이 아니라 **데이터** 문제 — 지금 업체가 하나뿐이다 |

## 1. 빌드 전 확인

- [ ] `npx tsc --noEmit` 통과
- [ ] **커밋 완료** — EAS는 git에서 소스를 가져간다. 커밋하지 않은 변경은 빌드에 들어가지 않는다


> 빌드 경로에 아포스트로피·공백·한글이 있어 실패하면 `EAS_NO_VCS=1`을 붙인다
> (2026-09-09에 확인된 우회).

## 2. 준비 — 계정과 기기

푸시는 **받는 사람이 정해져야** 보낼 수 있다. 최소 구성:

| 계정 | 역할 | 기기 |
|---|---|---|
| 관리자(Google) | 승인·답변·신고처리를 **누르는 쪽** | A |
| 업체 A(Google) | 알림을 **받는 쪽** | B |
| 업체 B(Google) | 순위 경쟁 상대 | B(로그아웃 후 전환) 또는 C |
| 고객(Google) | 매물 클릭·신고·QA 질문 | A 또는 C |

**기기 2대를 권한다.** 한 대에서 로그아웃/로그인을 반복하면 같은 기기 토큰의 주인이 바뀌어
이전 계정 푸시가 끊긴다. 의도된 동작이지만 테스트가 헷갈린다.

**앱 설치 후 각 계정으로 한 번씩 로그인**해야 토큰이 등록된다. 알림 권한 팝업은 반드시 허용한다.

> preview 빌드에는 아이디/비번 로그인이 **보이지 않는다**(`__DEV__` 가드).
> 실기기 테스트는 소셜 로그인으로만 한다.

---

## 3. 푸시 — 이번 빌드의 핵심

### 3-1. 토큰 등록 확인 (가장 먼저)

푸시가 안 오면 원인이 "보내는 쪽"인지 "받는 쪽"인지부터 갈라야 한다.

각 계정으로 로그인한 뒤 SQL Editor에서:

```sql
select u.email, t.platform, t.lang, t.updated_at
from public.push_tokens t
join auth.users u on u.id = t.user_id
order by t.updated_at desc;
```

- [ ] 로그인한 계정 수만큼 행이 있다
- [ ] `lang`이 채워져 있다(`ko` 등) ← **비어 있으면 푸시가 베트남어로 나간다**
- [ ] `platform`이 `android`다

행이 없으면 → 알림 권한을 거부했거나, 앱이 로그인 직후 등록에 실패한 것이다.

### 3-2. 충전 승인 푸시

1. 기기 B에서 업체 A로 **충전 신청**(100,000 이상)
2. 기기 A에서 관리자로 `MY > 정산 관리` → 그 신청의 **확인** → 실입금액 입력 → 확인 처리
3. **기기 B에 푸시가 도착**한다

- [ ] 푸시 도착
- [ ] 제목 "충전 승인", 본문에 **실제 입금액**이 들어간다(신고액이 아니라)
- [ ] 푸시를 누르면 광고비 정산 화면으로 이동
- [ ] 앱을 열면 `MY > 알림`에도 같은 알림이 남아 있다

**두 번 누르기**: 관리자가 같은 건을 다시 눌러도 **푸시는 한 번만** 가야 한다(`pushed_at`).

### 3-3. 푸시 언어 — 이번에 고친 부분

예전에는 모든 푸시가 한국어로 나갔다. 기기 언어를 따라가는지 본다.

1. 기기 B에서 **앱 언어를 English로 변경**(`MY > 설정 > 언어`)
2. **로그아웃 → 다시 로그인** ← 토큰의 `lang`은 등록 시점에 저장된다. 이 단계를 건너뛰면 예전 언어로 온다
3. 3-2를 한 번 더 수행(새 충전 신청 → 승인)

- [ ] 푸시가 **영어로** 도착한다 ("Top-up approved / … has been added to your balance.")
- [ ] 앱 안의 알림 수신함도 영어

### 3-4. 업체 승인 / QA 답변 푸시

- [ ] 관리자가 업체 신청을 승인 → 신청한 계정에 푸시 + 수신함
- [ ] 고객이 `고객센터`에 질문 → 관리자가 답변 → **질문자에게** 푸시 + 수신함

### 3-5. 광고 푸시 (잔액 소진 / 순위 탈락)

**잔액 소진** — 잔액을 일부러 바닥낸다.

1. 업체 A의 잔액을 작게 만든다(클릭 단가보다 조금 큰 정도). 관리자 `정산 관리`에서
   새 충전을 **작은 실입금액**으로 승인하거나, 클릭 단가를 잔액에 가깝게 올린다
2. 고객 계정(다른 기기)에서 그 광고 매물을 클릭
3. 마지막 클릭은 **남은 잔액만큼만** 차감되고 잔액이 0이 된다

- [ ] 업체 A에 "광고비 소진" 푸시
- [ ] 그 매물이 홈·부동산 추천에서 **사라진다**
- [ ] 순위표에서도 빠지고, 아래 순위가 올라온다

**순위 탈락** — 업체가 2곳 있어야 한다.

1. 업체 B로 같은 자리에 **더 높은 금액**으로 진입
2. 자리 수(추천 5 / TOP10 10)를 넘으면 맨 아래가 밀려난다

- [ ] 밀려난 업체에 "광고 순위 탈락" 푸시
- [ ] 밀려난 매물이 순위표에서 **삭제**된다(자동 복귀하지 않는다 — 다시 설정해야 한다)

## 4. 클릭 과금 — 실기기에서 다시 확인하는 이유

웹에서 통과했지만 **한 번 더 본다.** 이번 검증에서 "화면상 멀쩡한데 실제로는 과금이 전혀
안 되던" 결함을 찾았기 때문이다. 같은 부류는 눈으로 판정하면 안 된다.

1. 고객 계정(업체와 **다른 계정, 다른 기기**)에서 추천 매물 카드를 클릭
2. 업체 계정에서 `MY` 상단 숫자와 `광고비 정산 > 광고내역` 확인

- [ ] 주황 숫자(차감 합산)가 **클릭 단가만큼 늘어난다**
- [ ] 광고내역에 그 매물 이름으로 한 줄이 추가된다
- [ ] 같은 기기에서 1시간 안에 다시 클릭 → **더 늘어나지 않는다**

> 숫자가 변하지 않으면 `MY > 설정 > 알림`이 아니라 **콘솔/함수 로그**를 본다.
> 이제 앱이 `chargeAdClick server error`를 남기므로 실패는 조용히 지나가지 않는다.

## 5. 지도 · 사진 · 로그인

- [ ] 부동산 탭 우측 상단 **지도 토글** → 마커가 뜬다
- [ ] 매물 상세 `위치` 영역에 지도가 뜬다(웹에서는 "표시할 위치 정보가 없습니다")
- [ ] 매물 등록에서 **사진 촬영·선택** → 업로드 → 목록 썸네일에 반영
- [ ] `MY > 프로필 편집` → 사진 업로드
- [ ] 상담에서 사진 전송
- [ ] **Google 로그인** 4개 계정 전부
- [ ] 로그인 후 원래 보던 화면으로 돌아오는지

### 위치·거리

- [ ] 앱 첫 실행 시 **위치 권한 팝업**이 뜬다
- [ ] 허용하면 홈 상단에 현재 주소가 뜬다
- [ ] 매물 목록 우측 하단 **거리(km)** 가 그럴듯한 값이다
      (웹에서는 1111km 같은 값이 나왔다 — 기기 실좌표로 다시 본다)

## 6. 회귀 — 이번 세션에 건드린 화면

- [ ] 각 화면 **뒤로가기** (특히 팝업·하위 화면을 다녀온 뒤)

- [ ] 매물 리스트 배지(흰 배경) · 매물 사이 dashed 구분선
- [ ] 추천 캐러셀 3초 자동 슬라이드 · 화살표 위치
- [ ] 홈 투자/매물 토글 색상과 눌린 느낌
- [ ] 설명이 **기기 언어로** 번역되어 보이는지(매물명·주소는 원문)

## 7. 판정 기준

**통과**: 위 항목이 전부 ✓ 이고, 실패한 것이 하나도 "나중에 확인"으로 남지 않았다.

**주의해야 할 거짓 통과**

- 화면에 보이는 것만으로 판단하지 않는다. **숫자와 DB**를 함께 본다
  (광고가 보인다 ≠ 과금된다 — 이번에 실제로 겪었다)
- 푸시가 안 오면 "원래 늦나 보다"로 넘기지 않는다. 3-1의 토큰 조회부터 다시 한다
- 한 계정으로 모든 역할을 테스트하지 않는다. 자기 광고를 자기가 클릭하는 것은
  실사용과 다르다

**문제를 찾으면** 웹 미리보기(`npx expo start --web`)에서 재현해 본다 — 아이디/비번
로그인이 거기서는 살아 있어 계정 전환이 빠르고, 고쳐서 다시 빌드하기 전에 확인할 수 있다.

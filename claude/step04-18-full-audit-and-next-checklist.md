## 1. 검토에서 찾은 결함과 조치

### (A) 부동산 탭 추천 캐러셀에 클릭 과금이 없었다 — 수정함

같은 광고 매물인데 **홈에서 누르면 과금되고 부동산 탭에서 누르면 과금되지 않았다.**
광고주 입장에서는 클릭 수와 차감액이 맞지 않고, 플랫폼은 노출 비용을 회수하지 못한다.

또 부동산 탭의 추천 목록을 `properties.featured` 플래그로 뽑고 있어서,
**잔액이 소진되어 자리에서 빠진 매물이 계속 추천에 남을 수 있었다.**

조치 — `app/(tabs)/property.tsx`
- `listActiveAdSlots("featured")`로 **실제 살아 있는 광고 자리**를 받아 그 순서대로 노출
- 광고가 하나도 없을 때만 예전처럼 `featured` 플래그(관리자 수동 큐레이션)를 사용
- 캐러셀에서 누르면 `chargeAdClick(id, "featured")` 후 이동 (홈과 동일)

### (B) 유료 노출광고 화면에 거래완료·보류 매물이 섞여 있었다 — 수정함

`MY > 유료 노출광고`의 매물 목록이 상태를 가리지 않아, **거래완료 처리한 매물에도
광고를 걸 수 있었다.** 걸어도 고객 화면에는 나오지 않는다(조회가 `status='active'`만 본다).
돈을 넣고 아무 일도 일어나지 않는 길이 열려 있었다.

조치 — `app/ad-manage.tsx`: 목록을 `status === "active"`로 필터.

### (C) 서버에 매물 공개 상태 검증이 없었다 — 수정함

09-12에 "공개를 벗어나면 자리를 반납한다"는 트리거(`20260913120000`)를 넣었지만,
**반대 방향 — 이미 비공개인 매물이 새로 자리를 사는 길 — 은 막혀 있지 않았다.**
화면에서 (B)를 고쳐도 RPC를 직접 부르면 그대로 통과한다. 그렇게 만들어진 자리는
고객에게 절대 노출되지 않으면서 남의 자리만 막는 유령 행이 된다.

조치 — 새 마이그레이션 `20260913180000_ad_bid_require_active.sql`
- `set_ad_bid`가 권한 확인 후 `status <> 'active'`이면 `not-active`를 반환
- 권한 확인 **뒤에** 상태를 보도록 순서를 잡았다 — 남의 매물 상태를 오류로 흘리지 않기 위해
- 클라이언트: `services/ads.ts`에 `not-active` 추가, `app/ad-slots.tsx`에 안내 토스트
- i18n 6개 언어에 `adSlots.notActive` 추가 (**938키 6개 언어 일치 확인**)

## 2. 이상 없음을 확인한 항목

| 항목 | 확인 내용 |
|---|---|
| i18n 정합성 | ko/en/ja/vi/zh/th **938키 전부 일치**, 누락·여분 없음 |
| 광고 진입 경로 | `MY > 유료 노출광고` 단일 경로. 매물등록 폼에 남은 진입점 없음 |
| 내 매물 '추천' 탭 | 상태 변경이 아니라 `/ad-manage`로 보냄 (광고는 상태가 아니다) |
| 거래완료 → 광고 반납 | DB 트리거가 자리 삭제 + `featured` 해제. 화면도 같은 가정으로 갱신 |
| 클릭 과금 중복 방지 | IP 해시 + 1시간 창. 소금은 엣지 함수 시크릿에만 존재(번들에 없음) |
| 잔액 소진 처리 | 마지막 클릭은 잔여금만 차감 → 자리 전체 삭제 → 푸시 |
| 순위 인하 | 자리를 가진 매물은 최소금액 이상이면 인하 가능. 자기 탈락 시 알림 생략 |
| 푸시 설정 | `expo-notifications` 플러그인 + EAS projectId 존재. 실기기에서만 토큰 발급 |
| 권한 경계 | `agency_available_internal`은 클라이언트 실행 권한 없음. `set_ad_bid`는 호출자 JWT로 실행 |
| 뒤로가기 | 공용 `BackButton`(`canGoBack()` → 없으면 fallback `replace`) 18개 화면 적용 |

## 3. 아직 확인하지 못한 것 (코드로는 알 수 없음)

- **푸시 실수신** — 실기기 + 새 빌드가 있어야 확인 가능. 에뮬레이터·웹은 토큰을 발급하지 않는다.
- **클릭 과금 실차감** — 관리자 최소금액 설정 → 충전 → 광고 등록 → 홈 노출 → 클릭까지
  한 번은 실제로 돌려 봐야 한다(아래 5절 순서).
- **다중 사용자 경합** — 두 업체가 같은 순간에 같은 자리를 살 때의 순서. 현재는 DB 한 트랜잭션
  안에서 처리하므로 이론상 안전하지만 실측하지 않았다.

# 확정-결정사항

작성 2026-09-16 · **Dong이 직접 판단한 것만 적는다.** 제 추정은 여기 들어가지 않는다.

> ## 이 문서를 쓰는 법
>
> - 여기 적힌 것은 **결정**이다. 코드와 DB는 이 문서를 따라간다.
> - 결정을 바꾸면 **줄을 지우지 말고 "변경 2026-MM-DD"로 이어 적는다.** 왜 바꿨는지가
>   다음 사람에게 필요하다.
> - 아직 안 정한 것은 6절 〈미결〉에 둔다. **미결을 추정으로 메우지 않는다.**
> - 결정 하나가 여러 파일을 건드리면 4절 작업 목록에 그 파일을 다 적는다.

### 결정 사이의 연결

- **8 → 10**: 시행사(`developer_id`)를 화면에 넣으려면 `developers` 표에 데이터가 있어야 한다.
  그래서 10에서 `developers`만 살린다.
- **6 → 7**: 순위 검사를 넣으려면 어차피 `set_ad_bid`를 고쳐야 하므로, 반환 코드 분리도
  같은 마이그레이션에서 한다. **`set_ad_bid`는 8번째 재정의가 된다.**
- **1 → 9**: 기기 저장이 먼저고, `profiles` 동기화는 그 위에 얹는다. 비로그인 사용자는
  기기 저장만 쓴다.


### 작업하면서 추가로 정해진 것 (2026-09-16)

구현에 들어가서야 드러난 갈림길들이다. 원래 결정을 바꾼 것이 아니라, **결정만으로는
정해지지 않던 빈칸**을 메운 것이다.

| 언제 | 물음 | 정한 것 |
|---|---|---|
| 8·10 작업 중 | `developers` 표가 0행이고 정책이 관리자 전용인데, 시행사를 어떻게 받나 | **자유 입력 → 이름으로 자동 등록**(`upsert_developer`). 관리자 전용 관리 화면을 따로 두지 않는다 — 화면이 하나 늘고, 관리자가 먼저 넣어 두지 않으면 중개업자가 매물을 등록할 수 없다 |
| 5 작업 중 | 모집이 끝난 상품을 목록에서 어떻게 하나 | **목록에서 숨긴다. 단, 투자한 사람은 자기 상품을 계속 볼 수 있다.** 그래서 기간 필터를 RLS가 아니라 조회 쿼리에 두고, `app/my-investments.tsx`를 새로 만들었다 |
| 6 작업 중 | 순위 경쟁에서 지면 어떻게 하나 | **거절하고 화면이 자리 목록을 다시 읽어 현재 금액을 보여 준다.** 자동으로 한 단계 아래 순위에 넣지 않는다 — 사용자가 의도하지 않은 자리에 돈을 쓰게 된다 |
| 2 작업 중 | 이메일 로그인이 `__DEV__`로 감춰져 있어 이번 빌드에 안 나온다 | **`__DEV__`를 걷어내고 로그인·가입 둘 다 정식 기능으로 살린다.** 이유는 테스트 편의가 아니라 심사다 — 앱스토어 심사에 로그인 계정을 제출해야 하고, 소셜 전용이면 심사자가 구글 보안 차단에 걸려 심사가 진행되지 않는다 |
| 11 보고서 후 | 정책 감사에서 나온 결함 3건 | **13번만 고친다**(`property_images_select_permitted`). 14·15는 미결 — 빌드 직전에 권한을 더 건드리지 않는다 |

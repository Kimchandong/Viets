## 3. 2026-09-12 반영분

### 3.1 유료광고 (커밋 `efc465b`)

입찰 방식으로 만들었다가 **클릭당 과금**으로 전환했다. 마이그레이션 12건, 엣지 함수 2개.

- 자리: 추천 5개 / TOP10 10개. 밀려나면 차감 없이 자리에서 삭제되고, 다시 사야 한다
- 잔액 소진: 마지막 클릭은 잔여금만 차감 → 자리 전체 삭제 → 푸시
- 중복 클릭: IP 해시 + 1시간 창. 소금은 엣지 함수 시크릿에만 존재(번들에 없음)
- 진입점: `MY > 유료 노출광고` 단일 경로(폼 → 목록 → 선택모드 → 전용 화면으로 3번 옮긴 결과)

> **배운 것**: `agency_balance()`는 호출자가 멤버일 때만 값을 준다. 광고 노출 판정에
> 그대로 쓰면 **모든 판정이 0**이 된다 — 판정용 `agency_available_internal()`을 따로 뒀다.
> 같은 이유로 `my_active_agency_id()`도 판정에 쓸 수 없었다(`property_listing` 권한 요구).

### 3.2 허위매물 신고 / 거래완료 / 뒤로가기

- 신고는 (매물, 신고자) 유일키로 1인 1건. 관리자 목록은 매물 단위로 묶어 건수를 함께 보여 준다
- 거래완료·보류 시 광고 자리 자동 반납(트리거). 되돌려도 자동 복귀하지 않는다(사용자 결정)
- `router.back()`은 히스토리가 없으면 **조용히 아무 일도 하지 않는다.** 공용 `BackButton`
  (`canGoBack()` → 없으면 fallback `replace`)으로 18개 화면 일괄 수정

### 3.3 콘텐츠 번역 확장 (미커밋)

`properties` / `investment_products`에 `description_i18n`(jsonb) + `description_lang` 추가.
게시판에서 검증된 "저장 시점 번역"을 그대로 적용했다.

- 수정 시 **설명이 바뀌지 않았으면 재번역하지 않는다** — 가격만 고치는 수정이 대부분이다
- 기존 데이터는 `description_lang`이 NULL이라 모든 언어에서 원문이 보인다(이전과 동일)
- `translateOnce`를 `services/contentTranslation.ts`로 꺼내 게시판과 공유

### 3.4 알림 수신함 (미커밋)

`user_notifications` + `notification_preferences` + `notify_user()`.

- 문구를 DB에 넣지 않는다. **kind + params만** 저장하고 문장은 앱이 i18n으로 만든다 —
  6개 언어이므로 문장을 저장하면 다른 언어 사용자가 남의 언어를 읽게 되고, 언어를 바꿔도
  지난 알림은 그대로 남는다
- 알림이 생기는 지점을 **트리거로** 연결했다. 업체 승인/반려, 충전 승인/반려, QA 답변,
  신고 처리, 광고 2종(`ad_notifications` 미러링) — 기존 함수는 한 줄도 바뀌지 않았다
- 수신 설정은 `notify_user()`가 확인한다. 꺼 두면 수신함에도 쌓이지 않는다
### 3.5 푸시 다국어 + 수신함 푸시 (미커밋)

**발견한 결함**: 기존 푸시(광고 2종)가 **한국어 문자열로 박혀 있었다.** 앱 안은 6개 언어인데
앱 밖(푸시)만 한국어라, 베트남 사용자도 한국어 푸시를 받고 있었다.

- `push_tokens.lang` — 언어는 사용자가 아니라 **기기** 단위다(한 사람이 한국어 폰과
  베트남어 폰을 쓸 수 있고, 각 기기가 자기 언어로 받아야 한다)
- `supabase/functions/_shared/pushText.ts` — 발송 쪽 문구 카탈로그(8종 × 6언어).
  i18n 문구의 **사본**이다. 푸시는 앱이 꺼져 있을 때 뜨므로 앱의 i18n을 쓸 수 없다.
  **문구를 고칠 때는 양쪽을 함께 고친다**
- 새 엣지 함수 `send-push` — 관리자 여부는 호출자 JWT로 `is_admin_or_above()`를 실행해
  DB가 판정한다. `pushed_at`으로 중복 발송을 막는다
- 트리거가 수신함에 넣고, **푸시는 누른 관리자의 클라이언트가 한 번 밀어 준다.**
  pg_net을 켜면 DB에 호출용 비밀값을 둬야 하고 그 값이 저장소에 남는다 — ad-bid와 같은 방식
- 푸시 탭 경로를 허용 목록으로 막았다(예전엔 `/my`만 통과하고 나머지는 무시됐다)

### 3.6 RLS 전수 점검 (미커밋)

35개 표 전부 RLS 켜짐 / GRANT 누락 없음 / `security definer` 함수 전부 `search_path` 고정 /
`to public` 권한 잔존 없음. 좁힌 것 2건:

- **`payment_settings`가 비로그인(anon)도 읽을 수 있었다** — 은행명·예금주·계좌번호·QR이
  들어 있다. 같은 예금주 이름으로 다른 계좌를 안내하는 사칭이 쉬워진다. 읽는 화면 둘 다
  로그인이 필요해 authenticated로 좁혀도 잃는 것이 없다
- `agency_permissions`도 anon 공개였는데 클라이언트에서 직접 읽는 곳이 없다

의도된 공개라 그대로 둔 것: `locations` / `property_categories`(참조 데이터),
`property_ad_slots`(순위표는 경쟁 금액이 보여야 성립 — 오버추어 방식),
`ad_click_log` / `translation_cache`(RLS만 켜고 정책 없음 = 클라이언트 전면 거부가 의도).

## 7. 프로세스 원칙 (반드시 지킬 것)

1. DB 변경은 **migration으로만** (SQL Editor 금지)
2. 새 테이블에는 **GRANT를 함께** (3회 재발한 사고)
3. migration은 **멱등**하게
4. push 후 `npx supabase migration list`로 Local/Remote 일치 확인
5. 커밋·푸시는 **사용자 승인 후에만**
6. 새 라우트를 추가하면 `.expo\types` 삭제 후 expo 재기동
7. **문서가 아니라 코드를 확인하고 판단한다** — 이 문서도 예외가 아니다

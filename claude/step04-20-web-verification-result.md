## 1. 찾아서 고친 결함

### (1) 치명적 — 클릭 과금 전면 무효 `20260914150000`

**증상**: 광고 자리를 사고 홈·부동산에 노출까지 되는데, 눌러도 잔액이 1원도 줄지 않았다.

**원인**: `20260912150000`이 `charge_ad_click`을 다시 만들며
`revoke all ... from public, anon, authenticated`만 하고 **`service_role`에 execute를 주지 않았다.**
주석에는 "엣지 함수 ad-click 전용(service_role)"이라 적어 두고 정작 그 권한을 빠뜨렸다.

엣지 함수는 과금 실패를 **200 + `charged: 0`** 으로 삼키도록 만들어져 있었다(고객의 화면 이동을
막지 않으려는 의도). 그래서 앱에도 콘솔에도 아무 흔적이 없었다.

`set_ad_bid`가 멀쩡했던 이유는 반대다 — 그쪽은 `authenticated`에 권한을 주고 호출자 JWT로 실행한다.
**권한을 준 쪽만 동작했다.**

**조치**
- `grant execute on function charge_ad_click(...) to service_role`
- `ad-click`이 실패 시 `{ charged: 0, error: "charge-failed" }`를 돌려주고, 앱이 콘솔에 남긴다
- 검증: 500,000 → 498,999(Fuji 1,001) → 497,999(Harmony 1,000) 차감 확인

> **교훈**: security definer 함수에 `revoke`를 쓸 때는 **누가 부를 것인지**를 같은 자리에 적는다.
> 부를 사람에게 grant하지 않은 revoke는 기능을 조용히 끄는 것과 같다.

### (2) 비로그인 `permission denied` 5종

로그인 전용 표를 비로그인 상태에서도 그대로 조회하고 있었다. 화면은 빈 상태로 잘 떨어졌지만
방문자가 화면을 옮길 때마다 실패 요청이 반복되고 콘솔이 오류로 덮여 **진짜 문제를 가렸다**.

`my_unread_chat_count` / `my_new_investment_count` / `fetchMyRoles` /
`listNotifications` / `listDisabledNotificationKinds`

**조치**: `services/supabase.ts`에 `hasSession()`을 두고, 세션이 없으면 서버에 묻지 않는다.

### (3) 배지 불일치 (사용자 지시)

같은 화면에서 추천 캐러셀 배지는 흰 배경, 매물 리스트 배지는 파랑/주황이었다.
사용자 결정에 따라 **리스트 배지를 캐러셀 쪽(흰 배경 + 본문 글자색)으로 통일**했다.

## 3. 확인이 필요한 사항 (결함 아님 / 판단 필요)

### (a) 관리자 계정과 업체의 경계

`testadmin`은 `agency_members`에 **행이 없다**(관리자 계정). 그런데

- MY에 "승인된 중개업소 하이퐁 부동산", 잔액, "광고비 정산" 버튼이 **보인다**
- 광고 순위 진입과 클릭 과금이 **그 업체 잔액에서** 이뤄진다(`is_admin_or_above()` 경로)
- 그러나 **충전 신청은 거부된다**(`not-approved-agency` — 업체 멤버만 가능)

권한 검사는 각자 일관되지만, 화면에서는 "업체가 보이는데 충전은 안 되는" 상태다.
관리자 대행을 의도한 것이라면 그대로 두되 거부 사유를 화면에 분명히 보여 주고,
의도치 않았다면 경계를 좁혀야 한다. **사용자 결정 필요.**

### (b) 웹 데스크톱 폭에서 추천 캐러셀 카드 붕괴

브라우저 창이 넓을 때 캐러셀 카드가 세로로 찌그러진다. 모바일 폭(375px)에서는 정상이고
실제 제품은 모바일 앱이므로 우선순위는 낮다.

### (c) 운영 데이터 미입력

`payment_settings`의 은행명·예금주·계좌번호·QR이 비어 있어 입금 화면 안내가 비어 나온다.
